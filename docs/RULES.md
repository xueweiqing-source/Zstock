# 规则调参指南

平台内置 43 项分析规则，全部可在 **Web「规则与研判」页**调整，保存后**下次运行生效**（历史报告与回测记录不变）。

调整入口：登录 → 顶部导航「规则与研判」。

---

## 一、先看回测，再动参数

**强烈建议**：改动前先看 `/backtest` 的当前命中率基线，改动后跑 3-5 期观察变化，再决定是否保留。

回测命中口径：
- **看涨** 命中 = 预测后实际上涨
- **看跌** 命中 = 预测后实际下跌
- **震荡** 命中 = |实际涨跌| < `backtest_flat_pct`（默认 1%，每日口径）

> 单期数据有噪声，别因一次偏差就大改。看趋势。

## 二、参数详解

### 1. 三层权重与方向阈值（最常用）

| 参数 | 默认 | 含义 | 调参思路 |
|---|---|---|---|
| `w_fund` | 0.35 | 基本面权重 | 看重公司质地就调高 |
| `w_val` | 0.30 | 估值权重 | 价值风格调高，成长/趋势风格调低 |
| `w_tech` | 0.35 | 技术面权重 | 短线/趋势风格调高 |
| `dir_bull` | 62 | 综合分 ≥ 此值 → 看涨 | **命中率低且看涨过多 → 调高**（更严） |
| `dir_bear` | 45 | 综合分 < 此值 → 看跌 | 想更少看跌 → 调低 |

三层加权综合分 = (基本面×W1 + 估值×W2 + 技术面×W3) / 有效层权重和。

> **实测参考**：首版规则在下跌市中看涨 354 条仅命中 20.3%（看涨给太多）。此时应把 `dir_bull` 从 62 提到 70+，或提高技术面权重（下跌趋势中技术面会拉低分数）。

### 2. 基本面（值不值得买）

分档采用 `[[阈值, 加分], ...]` 从高到低匹配，未命中任何档取最后一档。

| 参数 | 默认 | 含义 |
|---|---|---|
| `fund_revenue_bands` | `[[20,22],[5,14],[0,6],[-10,-6]]` | 营收同比分档 |
| `fund_profit_bands` | `[[30,22],[10,14],[0,6],[-1000,-10]]` | 归母净利同比分档 |
| `fund_roe_bands` | `[[15,22],[8,14],[0,6],[-1000,-10]]` | ROE 加权分档 |
| `fund_debt_ok` | 50 | 负债率 < 此值 → +12（低杠杆） |
| `fund_debt_mid` | 70 | < 此值 → +4；≥ 此值 → −8 |
| `fund_cf_pos` | 0.05 | 经营现金流/营收 > 此值 → +10；为负 → −14 |
| `fund_verdict_good` | 68 | 得分 ≥ 此值判定「好公司」 |
| `fund_verdict_mid` | 42 | 得分 ≥ 此值判定「一般」，否则「质地偏弱」 |

> 资产负债率对金融/地产属正常高杠杆，报告中已标注需人工复核。想覆盖这类行业，可放宽 `fund_debt_mid`。

### 3. 估值（贵不贵）

| 参数 | 默认 | 含义 |
|---|---|---|
| `val_pe_cheap` | 15 | PE < 此值 → 低估（+`val_pe_cheap_score`） |
| `val_pe_fair` | 30 | PE < 此值 → 合理（+`val_pe_fair_score`） |
| `val_pe_expensive` | 60 | PE < 此值 → 偏贵（+`val_pe_exp_score`）；更高 → +`val_pe_high_score` |
| `val_pb_cheap` | 1.2 | PB < 此值 → 破净区（+18） |
| `val_pb_fair` | 3.0 | PB 分界 |
| `val_pb_expensive` | 6.0 | PB 高分界 |
| `val_pos_low` | 30 | 52 周股价位置 < 此值% → 低位（+22） |
| `val_pos_high` | 70 | 52 周位置分界 |
| `val_peg_good` | 1.0 | PEG < 此值 → 增速匹配估值（+20） |
| `val_peg_fair` | 2.0 | PEG 分界 |
| `val_verdict_cheap` | 62 | 得分 ≥ 此值判定「便宜」 |

> PE 为负（亏损）时判 −12 并提示改看 P/S；**不估算 P/S**，避免编数字。

### 4. 技术面（相对时机）

| 参数 | 默认 | 含义 |
|---|---|---|
| `tech_ma20_w` | 14 | 站上/跌破 MA20 的加减分绝对值 |
| `tech_ma60_w` | 13 | MA60 |
| `tech_ma120_w` | 9 | MA120 |
| `tech_macd_w` | 10 | MACD 柱正负的加减分绝对值 |
| `tech_rsi_overbought` | 70 | RSI ≥ 此值 → 超买（−6） |
| `tech_rsi_oversold` | 30 | RSI ≤ 此值 → 超卖（+6） |
| `tech_vol_confirm` | 1.2 | 5日均量/20日均量 > 此值视为放量 |
| `tech_pos_low` | 40 | 52 周位置 < 此值% → 中期赔率占优（+6） |
| `tech_verdict_bull` | 62 | 得分 ≥ 此值判定「偏多」 |

> 想让技术面信号更灵敏：调高 `tech_ma20_w`、`tech_macd_w`；想更钝化则调低。

### 5. 大盘广度

| 参数 | 默认 | 含义 |
|---|---|---|
| `breadth_healthy` | 55 | 上涨占比 ≥ 此值% → 赚钱效应好（+10） |
| `breadth_weak` | 42 | 上涨占比 ≤ 此值% → 赚钱效应差（−12） |
| `breadth_soft` | 48 | 介于 weak 与 soft 之间 → 偏弱（−5） |

### 6. 回测

| 参数 | 默认 | 含义 |
|---|---|---|
| `backtest_flat_pct` | 1.0 | 「震荡」方向的命中判定：\|实际涨跌\| < 此值% |

> 周度口径时代默认 3%；改每日后收敛到 1%。若觉得震荡判定太严/太松，可调。

## 三、常见调参场景

### 场景 A：看涨命中率明显偏低（看涨给太多）

```
dir_bull: 62 → 72        # 收紧看涨门槛
w_tech: 0.35 → 0.45      # 让趋势走坏时更难看涨
w_fund: 0.35 → 0.25
```

### 场景 B：看跌命中率偏低

```
dir_bear: 45 → 38        # 收紧看跌门槛（只有更弱才判跌）
```

### 场景 C：想更偏价值风格

```
w_val: 0.30 → 0.45
val_pe_cheap: 15 → 20    # 放宽低估认定
val_verdict_cheap: 62 → 55
```

### 场景 D：想更偏趋势/短线

```
w_tech: 0.35 → 0.50
w_val: 0.30 → 0.15
tech_ma20_w: 14 → 20
tech_macd_w: 10 → 15
```

### 场景 E：震荡判定太松/太严

```
backtest_flat_pct: 1.0 → 2.0   # 放松
backtest_flat_pct: 1.0 → 0.5   # 收紧
```

## 四、分档格式说明

`fund_revenue_bands` 这类参数是 JSON 数组，每项 `[阈值, 加分]`，**从高到低**匹配：

```json
[[20, 22], [5, 14], [0, 6], [-10, -6]]
```

含义：
- 值 ≥ 20 → +22（高增长）
- 值 ≥ 5 → +14（稳增长）
- 值 ≥ 0 → +6（微增）
- 值 ≥ −10 → −6（下滑）
- 值 < −10 → 取最后一档 −6

最后一档的阈值是「兜底线」，通常填一个很小的数（如 −1000）表示无下限。

## 五、恢复默认

「规则与研判」页底部有 **恢复默认规则** 按钮（只重置规则，LLM 配置不受影响）。

也可手动删除配置文件后重启：

```bash
rm -f /var/www/stock-forecast/data/rules_config.json
systemctl restart stock-forecast
```

## 六、LLM 研判配置

| 字段 | 说明 |
|---|---|
| 启用 | 关闭时全部走确定性规则 |
| API Base | OpenAI 兼容接口，如 `https://api.deepseek.com/v1` |
| API Key | 仅存服务器 `data/app_config.json`（已 gitignore） |
| 模型 | `deepseek-chat` / `mimo` 等 |

页面有 **测试 LLM 连接** 按钮，填好后点一下验证连通性。

> LLM 输出被硬约束：只允许基于传入数据推演、禁止编造点位、输出强制 JSON。调用失败自动回退规则，系统不中断。
> 建议 LLM 研判与量化指标**交叉验证**：两者方向不一致时报告会体现分歧，人工复核更有价值。
